# gcp-adk

A minimal, single-turn "hello world" agent built with Google's
[Agent Development Kit (ADK)](https://adk.dev) for Python, scaffolded with the
[Agents CLI](https://github.com/google/agents-cli), running against Gemini through
Vertex AI (Gemini Enterprise Agent Platform) using your GCP $300 Free Trial credit.

This is a prototype, not a production template: no deployment, no multi-agent
orchestration, no CI/CD. It exists to prove one thing end-to-end — a GCP account with
Free Trial credit, wired through a plain API key, into a locally-running ADK agent.

There are three milestones. Do them in order.

| # | Milestone | Where |
|---|-----------|-------|
| 1 | Get a Gemini API key that actually uses your $300 Free Trial credit | [GCP_SETUP.md](GCP_SETUP.md) |
| 2 | Wire that key into this repo | This doc, below |
| 3 | Run the agent locally via ADK + the Agents CLI | This doc, below |

Repo conventions (commit style, PR practice) live in [AGENTS.md](AGENTS.md).

## Prerequisites

- macOS (this guide assumes it; flagged inline where Linux/Windows differ)
- [uv](https://docs.astral.sh/uv/getting-started/installation/) — Python package/venv
  manager used for everything here. Install: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- Python is *not* a separate prerequisite — `uv` downloads and pins the right interpreter
  itself the first time you run a command in this repo (this project requires
  `>=3.11,<3.14`).
- A completed [Milestone 1](GCP_SETUP.md) — you need the API key before continuing.

You do **not** need `gcloud` installed, a service account key file, or
`gcloud auth login` for this prototype — everything below runs on a plain API key.

```
gcp-adk/

├── README.md                 # this file — Milestones 2-3
├── AGENTS.md                 # commit/PR/agent-context conventions
├── app/
│   ├── agent.py               # root_agent definition — model, instruction, tools

├── tests/
│   ├── unit/                  # structural tests, no API key needed
│   ├── integration/           # needs a real API key — exercises a live model call
│   └── eval/                  # agents-cli eval scenarios (not used in this prototype)
├── .env.example               # copy to .env, fill in your key
├── pyproject.toml             # uv-managed dependencies
├── agents-cli-manifest.yaml   # read by the agents-cli tool
└── Dockerfile                 # generated by agents-cli scaffold; unused — no deployment in this prototype
```

`app/agent.py` is the file you'd actually edit to change what the agent does. Everything
else under `app/` is generated wiring the Agents CLI relies on.

## Milestone 2: Wire the key into the repo

1. Copy the env template:
   ```bash
   cp .env.example .env
   ```
2. Open `.env` and paste the key from [Milestone 1](GCP_SETUP.md) in place of
   `YOUR_API_KEY_HERE`:
   ```env
   GOOGLE_GENAI_USE_VERTEXAI=TRUE
   GOOGLE_API_KEY="AIzaSy...your real key..."
   ```
3. Leave `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` **unset**. If either is
   present in the environment, the SDK silently drops your API key and requires
   `gcloud` ADC login instead — which this prototype deliberately doesn't use.
4. `.env` is already listed in `.gitignore` — `git status` should never show it as a
   change to commit. If it ever does, stop and check you didn't `git add -f` it.

Install dependencies:

```bash
uv sync
```

**Expected output:** a `Resolved N packages` / `Installed N packages` log ending
cleanly, and a new `.venv/` directory in the repo root.

## Milestone 3: Run it locally

This project was scaffolded by, and is meant to be driven by, the **Agents CLI**
(`agents-cli`) — not just plain ADK commands. Install it once (global CLI tool, not a
per-project dependency):

```bash
uv tool install google-agents-cli
```

Verify it can see this project:

```bash
agents-cli info
```

**Expected output** (version numbers and paths will differ on your machine):
```
CLI version:        1.3.1
CLI install path:   /path/to/uv/tools/google-agents-cli/...
OS info:            macOS-...
Installed skills:   none

Project root:       /path/to/gcp-adk
Project name:       app
Deployment target:  none
Agent directory:    app
Region:             us-east1
A2A:                yes
```
The `Installed skills: none` line refers to `agents-cli`'s own project-local skill
cache, unrelated to any Claude Code / coding-assistant skills you may have installed
separately — it's expected to say "none" here.

Install the project's own dependencies through the CLI (equivalent to `uv sync`, but
this is the Agents-CLI-native entry point):

```bash
agents-cli install
```

### Option A — interactive playground (recommended first run)

```bash
agents-cli playground
```

This starts a local web server and opens a browser UI where you can chat with the agent.
Ask it something like *"what's the weather in SF?"* — the scaffolded agent ships with a
`get_weather` and `get_current_time` tool, so a real response (not an error) confirms
the whole chain — API key → Vertex AI → ADK → tool call → reply — is working.

### Option B — one-off prompt from the terminal

```bash
agents-cli run "What's the weather in San Francisco?"
```

**Expected output:** the agent's tool-augmented reply printed to your terminal, e.g.
something like `It's 60 degrees and foggy in San Francisco.` — not an error, not empty
output.

### Option C — plain ADK CLI

The Agents CLI wraps ADK; you can also drop to ADK's own CLI directly if you prefer:

```bash
uv run adk run app
# or, for the browser dev UI:
uv run adk web
```

## Troubleshooting

- **`ValueError: No API key was provided`** — `.env` wasn't picked up, or still has the
  placeholder value. Confirm `.env` exists (not just `.env.example`) and that
  `GOOGLE_API_KEY` is your real key, run from the repo root (`.env` is only auto-loaded
  when it's next to `app/`).
- **`agents-cli: command not found`** — the `uv tool install` step above installs it as a
  global tool; open a new terminal, or run `uv tool update-shell` and restart your shell.
- **403 / permission errors calling the model** — almost always means the API key's
  backing service account is missing the "Gemini Enterprise Agent Platform Express User"
  role, or the Vertex AI API isn't enabled on the project the key belongs to. Re-check
  [GCP_SETUP.md](GCP_SETUP.md) steps 2–3.
- **It works but nothing shows up in Cloud Billing** — billing data can lag by hours;
  this doesn't mean the credit isn't being used.
- **Tests**: `uv run pytest tests/unit` runs with no API key required (structural checks
  only). `uv run pytest tests/unit tests/integration` additionally exercises a real model
  call and will fail without a valid `.env` — that's expected, not a bug.

## Non-goals (out of scope for this prototype)

Deployment (Cloud Run / Agent Runtime / GKE), CI/CD, multi-agent orchestration, and
production credential patterns (Application Default Credentials, service-account key
files) are all deliberately not covered here. The scaffold includes a `Dockerfile` and
A2A wiring because that's what `agents-cli scaffold create` always generates — they're
inert until you explicitly opt into deployment with `agents-cli scaffold enhance`.
